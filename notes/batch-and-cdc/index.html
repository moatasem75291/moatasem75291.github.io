Data architecture

Where batch and CDC meet

Keeping the initial snapshot and the change stream aligned.

A batch load gives you a point-in-time view. Change data capture records what happened after a source position. The handover between those two views is where a pipeline can introduce gaps or duplicates.

Define record keys and replay behavior before wiring downstream transformations. Where append-only history matters, keep source offsets and operation metadata with the raw events. When current state is the goal, make updates idempotent.

The useful comparison is whether the same validation rules still pass after a restart, a repeated event or a schema change.
